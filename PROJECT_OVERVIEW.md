## Executive Summary

**AI Deck Presenter** is a full-stack web application for managing and presenting AI-generated HTML slide decks. Users can upload self-contained HTML presentations (typically generated by AI tools like ChatGPT, Claude, etc.), organize them in a personal dashboard, and share them via unique public URLs.

The application solves a specific workflow problem: after generating a polished HTML presentation with an AI assistant, there's no straightforward way to host, manage, and share those presentations. AI Deck Presenter fills that gap with a clean upload-and-share pipeline.

**Key use cases:**
- Uploading AI-generated HTML slide decks for hosting and sharing
- Managing a personal library of presentations
- Sharing presentations via slug-based public URLs (`/p/{slug}`)
- Generating structured AI prompts to create new presentations (Prompt Builder)

## Core Features

### 1. Authentication
Email/password authentication powered by **Supabase Auth**. Sessions are managed via HTTP-only cookies (`sb-access-token`, `sb-refresh-token`). Unauthenticated users are redirected to `/login`.

### 2. Dashboard
A React-powered dashboard (`/dashboard`) where authenticated users can:
- View all their uploaded presentations in a responsive grid
- See presentation metadata (title, slug, description, public/private status, creation date)
- Open presentations in the viewer
- Copy shareable links to clipboard
- Delete presentations (removes both the database record and the stored file)

### 3. Presentation Viewer
A fullscreen-capable viewer at `/p/{slug}` that:
- Loads the HTML presentation via an iframe served through `/api/presentations/{slug}/serve`
- Provides floating controls (bottom-right) for fullscreen toggle and share link copy
- Respects access control: public presentations are viewable by anyone; private ones require the owner to be authenticated
- Uses `sandbox="allow-scripts allow-same-origin allow-popups allow-forms"` for security

### 4. Prompt Builder
A two-stage modal that helps users generate structured AI prompts for creating new presentations:
- **Configure stage**: Fill in topic, slide count, audience, language, purpose, visual style, content depth, and special requirements
- **Preview stage**: View the generated prompt and copy it to clipboard
- The prompt is designed to produce a single self-contained HTML file with professional design constraints

### 5. File Upload
A drag-and-drop upload modal that accepts `.html` files (max 10 MB):
- Auto-generates a URL slug from the title
- Validates slug uniqueness against the database
- Stores files in Supabase Storage at `decks/{userId}/{slug}.html`
- Records metadata in the `presentations` database table

### 6. Public & Private Visibility
Each presentation has an `is_public` flag. Public presentations are viewable by anyone with the link. Private presentations require the owner to be authenticated.

|  | /api/auth/*  |  | /api/present |  | /api/presentations/:slug |     |

+----------------------------------------------------------------------+
|                         Supabase                                      |

**Key architectural decisions:**
- **Server-side rendering (SSR)**: Astro renders pages on the server with `output: 'server'`. This is essential for cookie-based auth and protected routes.
- **React islands**: Interactive components (dashboard, modals, viewer controls) are hydrated client-side via React with `client:load`.
- **Supabase as BaaS**: All backend services (auth, database, file storage) are handled by Supabase — no custom backend server.
- **Vercel adapter**: The app is deployed to Vercel with `@astrojs/vercel` handling the SSR runtime.

## Data Model

### `presentations` table (Supabase/PostgreSQL)

The application uses a single `presentations` table. The schema is inferred from the application code:

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | `uuid` | Primary key (auto-generated) |
| `user_id` | `uuid` | Foreign key to `auth.users` (the owner) |
| `title` | `text` | Display title of the presentation |
| `slug` | `text` | Unique URL slug (used in `/p/{slug}`) |
| `description` | `text` | Optional description |
| `file_path` | `text` | Path in Supabase Storage (`decks/{userId}/{slug}.html`) |
| `ai_prompt` | `text` | Optional notes about the AI prompt used to generate the deck |
| `is_public` | `boolean` | Whether the presentation is publicly accessible (defaults to `true`) |
| `created_at` | `timestamptz` | Creation timestamp (auto-generated) |

**Row Level Security (RLS)** should be configured so users can only read/write their own presentations, while public presentations are readable by anonymous users.

## API Reference

### Authentication

#### `POST /api/auth/login`

Authenticates a user with email and password.

- **Request**: `application/x-www-form-urlencoded` with `email` and `password` fields
- **Success**: Sets `sb-access-token` and `sb-refresh-token` cookies, redirects to `/dashboard`
- **Error**: Redirects to `/login?error={message}`

**Cookie details:**
- `httpOnly: true` — Not accessible via JavaScript
- `secure: true` (in production) — HTTPS only
- `sameSite: lax` — Sent on top-level navigations
- `path: /` — Available on all routes

#### `GET /api/auth/signout`

Clears session cookies and redirects to `/login`.

- **Request**: No body required
- **Response**: Deletes `sb-access-token` and `sb-refresh-token` cookies, redirects to `/login`

### Presentations

#### `GET /api/presentations`

Returns all presentations belonging to the authenticated user.

- **Auth**: Required (cookie-based session)
- **Response**: `{ presentations: Presentation[] }` ordered by `created_at` descending
- **Error**: `401 Unauthorized` if no valid session

#### `POST /api/presentations`

Uploads a new presentation.

- **Auth**: Required (cookie-based session)
- **Request**: `multipart/form-data`
  - `title` (required) — Presentation title
  - `slug` (required) — URL slug (must be unique)
  - `file` (required) — HTML file (max 10 MB)
  - `description` (optional) — Short description
  - `ai_prompt` (optional) — AI prompt notes
- **Success**: `201 Created` with `{ presentation: Presentation }`
- **Errors**:
  - `400` — Missing required fields or file too large
  - `401` — No valid session
  - `409` — Slug already exists
  - `500` — Upload or database failure

**Behavior:**
1. Validates session via Supabase Auth
2. Validates required fields and file size
3. Checks slug uniqueness in the database
4. Uploads file to Supabase Storage at `decks/{userId}/{slug}.html`
5. Inserts metadata into the `presentations` table
6. On database insert failure, cleans up the uploaded file

#### `DELETE /api/presentations/{id}`

Deletes a presentation owned by the authenticated user.

- **Auth**: Required (cookie-based session)
- **Response**: `200 OK` with `{ success: true }`
- **Errors**:
  - `400` — Missing ID
  - `401` — No valid session
  - `404` — Presentation not found or not owned by user
  - `500` — Storage or database deletion failure

**Behavior:**
1. Validates session and ownership
2. Deletes the file from Supabase Storage
3. Deletes the database record

#### `GET /api/presentations/{slug}/serve`

Serves the raw HTML content of a presentation with correct `Content-Type`.

- **Auth**: Not required for public presentations; required for private ones
- **Response**: `200 OK` with `Content-Type: text/html; charset=utf-8` and `Cache-Control: public, max-age=300`
- **Errors**:
  - `404` — Presentation not found, or private and user is not the owner
  - `500` — File download failure

## Authentication Flow

```
+----------+     +--------------+     +--------------+     +-----------+
|  User     |     |  Login Page  |     |  /api/auth/  |     | Supabase  |
| (Browser) |     |  (Astro SSR) |     |  login       |     | Auth      |
+-----+-----+     +------+-------+     +------+-------+     +-----+-----+
      |                  |                    |                   |
      |  GET /login      |                    |                   |
      |----------------->|                    |                   |
      |                  |                    |                   |
      |  POST email +    |                    |                   |
      |  password        |                    |                   |
      |------------------------------------->|                   |
      |                  |                    | signInWithPassword|
      |                  |                    |------------------>|
      |                  |                    |                   |
      |                  |                    |  access_token +   |
      |                  |                    |  refresh_token    |
      |                  |                    |<------------------|
      |                  |                    |                   |
      |                  |   Set cookies:     |                   |
      |                  |   sb-access-token  |                   |
      |  302 /dashboard  |   sb-refresh-token |                   |
      |<-------------------------------------|                   |
      |                  |                    |                   |
      |  GET /dashboard  |                    |                   |
      |  (cookies sent)  |                    |                   |
      |------------------------------------------------------->|
      |                  |                    |  session valid    |
      |  Dashboard HTML  |                    |                   |
      |<-------------------------------------------------------|
```

**Session validation on protected pages (e.g., `/dashboard`):**
1. Read `sb-access-token` and `sb-refresh-token` from cookies
2. Call `supabase.auth.setSession()` to validate/refresh the session
3. If invalid, delete cookies and redirect to `/login`
4. If valid, extract user info and render the page

**Session validation on API routes:**
1. Same cookie-based validation
2. Returns `401 Unauthorized` JSON response if invalid

## Key Components

### `DashboardApp.tsx`
The main orchestrator for the dashboard page. Manages:
- Modal state (upload modal open/closed, prompt modal open/closed)
- Refresh trigger (increments when a new presentation is uploaded to re-fetch the grid)
- Renders the action buttons ("New Deck", "Prompt Builder"), `PresentationGrid`, `UploadModal`, and `BasicPromptModal`

### `UploadModal.tsx`
A Framer Motion-animated modal for uploading HTML presentations:
- Drag-and-drop file zone with visual feedback
- Accepts only `.html`/`.htm` files, max 10 MB
- Auto-generates slug from title (editable)
- Fields: title (required), slug (required), description (optional), AI prompt notes (optional)
- Submits via `multipart/form-data` to `POST /api/presentations`

### `PresentationGrid.tsx`
Displays presentations in a responsive CSS Grid (`auto-fill, minmax(300px, 1fr)`):
- Each card shows title, slug, description, public/private badge, and creation date
- Actions per card: View (opens `/p/{slug}`), Copy Link, Delete
- Animated entrance/exit with Framer Motion `AnimatePresence`
- Loading state with spinner, empty state with placeholder

### `BasicPromptModal.tsx`
A two-stage modal for generating AI presentation prompts:
- **Configure stage**: Form fields for topic, slide count, slide structure, audience, language, purpose, visual style, content detail level, special requirements, and output format
- **Preview stage**: Shows the generated prompt in a scrollable text area with a "Copy Prompt" button
- Uses `generatePresentationPrompt()` from `prompt-generator.ts`

### `FloatingControls.tsx`
Floating overlay controls for the presentation viewer:
- **Fullscreen toggle**: Uses the browser Fullscreen API (`document.documentElement.requestFullscreen()`)
- **Share button**: Copies the presentation URL to clipboard with animated "Copied!" feedback
- Positioned at bottom-right with `fixed` positioning
- Glassmorphism styling (backdrop blur, semi-transparent background)
- Animated entrance with Framer Motion (delayed fade-in)

### `Layout.astro`
The base HTML layout used by all pages:
- Sets up `<html>`, `<head>` (charset, viewport, favicon, meta), and `<body>`
- Loads Google Fonts: **Inter** (weights 400-700) and **JetBrains Mono** (weights 400-600)
- Imports `global.css`
- Uses `<slot />` for page content

## File Storage

### Supabase Storage Bucket: `decks`

Files are stored with the following path structure:

```
decks/
└── {user_id}/
    └── {slug}.html
```

**Example:** `decks/a1b2c3d4-.../my-awesome-presentation.html`

**Storage configuration:**
- Content type: `text/html`
- Upload mode: `upsert: true` (overwrites existing files with the same path)
- Max file size: 10 MB (enforced client-side and server-side)

**Serving:** The `/api/presentations/{slug}/serve` endpoint downloads the file from storage and serves it with `Content-Type: text/html; charset=utf-8` and a 5-minute cache (`Cache-Control: public, max-age=300`).

## Environment Setup

### Prerequisites

- **Node.js** >= 22.12.0
- **[Bun](https://bun.sh)** — Install with `curl -fsSL https://bun.sh/install | bash`
- A **[Supabase](https://supabase.com)** project

### Supabase Configuration

1. **Create a Supabase project** at [supabase.com](https://supabase.com)

2. **Enable Email/Password auth** in Authentication > Providers

3. **Create the `presentations` table** in the SQL Editor:

   ```sql
   create table presentations (
     id uuid primary key default gen_random_uuid(),
     user_id uuid references auth.users(id) on delete cascade not null,
     title text not null,
     slug text unique not null,
     description text,
     file_path text not null,
     ai_prompt text,
     is_public boolean default true,
     created_at timestamptz default now()
   );

   -- Enable RLS
   alter table presentations enable row level security;

   -- Owners can do everything with their own presentations
   create policy "Users can manage own presentations"
     on presentations for all
     using (auth.uid() = user_id);

   -- Anyone can read public presentations
   create policy "Public presentations are readable"
     on presentations for select
     using (is_public = true);
   ```

4. **Create a Storage bucket** named `decks`:
   - Go to Storage > New Bucket
   - Name: `decks`
   - Public: No (files are served through the API)

5. **Set Storage policies**:

   ```sql
   -- Owners can upload/manage their own files
   create policy "Users can upload own decks"
     on storage.objects for insert
     with check (bucket_id = 'decks' and auth.uid()::text = (storage.foldername(name))[1]);

   create policy "Users can read own decks"
     on storage.objects for select
     using (bucket_id = 'decks' and auth.uid()::text = (storage.foldername(name))[1]);

   create policy "Users can delete own decks"
     on storage.objects for delete
     using (bucket_id = 'decks' and auth.uid()::text = (storage.foldername(name))[1]);
   ```

### Environment Variables

Create a `.env` file in the project root:

```env
PUBLIC_SUPABASE_URL=https://your-project.supabase.co
PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

Both variables are prefixed with `PUBLIC_` so they are available on both client and server.

## Deployment

The project is configured for deployment on **[Vercel](https://vercel.com)** with server-side rendering.

### Configuration

- **Adapter**: `@astrojs/vercel` (configured in `astro.config.mjs`)
- **Output mode**: `server` (all pages are SSR by default)
- **Static pages**: `/p/[slug].astro` explicitly sets `export const prerender = false` since it needs dynamic data

### Deploy Steps

1. Push the repository to GitHub (or your preferred Git host)
2. Connect the repository to Vercel
3. Set the environment variables (`PUBLIC_SUPABASE_URL`, `PUBLIC_SUPABASE_ANON_KEY`) in the Vercel project settings
4. Vercel will automatically build and deploy on every push

Alternatively, deploy manually:

```sh
# Build for production
bun build

# Preview locally
bun preview

# Deploy with Vercel CLI
npx vercel
```
